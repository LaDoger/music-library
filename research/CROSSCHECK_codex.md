# Codex cross-check: agent music libraries

Checked 2026-10-09 by Codex (gpt-6.1-sol), against `agent_music_libraries.md`. Evidence comes from primary project sites, repositories, dataset releases and provider terms, using web search plus direct HTTP fetches. Scores below are review judgments, not legal clearance. No library items were imported or marked verified.

## Verdict: disagree on the broad novelty claim

The claims **“Novel? Yes, as an agent-facing production library”** and **“Nothing found scored 4 or 5”** are too strong. **Keynata Commons scores 4/5**: a working, downloadable, multi-category catalogue combines editable MIDI, rendered audio, CC0 declarations, per-track metadata and a static JSON index. The index fetched in this check contains **203 tracks in seven categories**, with **234 MIDI and 234 MP3 files** across versions. A sample MIDI, MP3 and metadata record all returned HTTP 200; the MIDI has a valid `MThd` signature. These are observed files, not a proposed product. [Live index](https://carf-coder.github.io/keynata-commons/release/index.json), [sample metadata](https://carf-coder.github.io/keynata-commons/release/tracks/classical_duo_24000/metadata.json), [release licence](https://carf-coder.github.io/keynata-commons/release/LICENSE.txt).

It does not earn 5: its music is generated and synthesized, its licence covers generated content together rather than independently documenting acquired score and performance rights, and quality/recognisability was not established by this check. Its index lists no WAV files despite the homepage advertising WAV downloads. Its screening claims also remain publisher assertions. Nevertheless, the report's definition accepts MIDI, static JSON and PD/CC content; excluding this precedent just because it is generated would change that definition. [Project description](https://carf-coder.github.io/keynata-commons/), [implementation and third-party notices](https://github.com/carf-coder/keynata-commons).

**The narrower differentiation remains plausible:** a curated library of recognisable repertoire for commercial/social edits, with independently evidenced score and recording rights, excerpts, moods, credit text, CLI rendering and convenient agent access. No exact equivalent to that narrower package was established. Open Goldberg/OpenWTC and MusicNet already demonstrate score–recording pairings; Epidemic already demonstrates a production-oriented catalogue MCP. Novelty should therefore describe the curation and rights documentation, not the existence of machine-readable music libraries or joined scores and audio.

## Confirmed reusable sources, ranked for this library

“Confirmed” here means a real source and an observed rights statement, not that every file is cleared. These rankings prioritise strong editable editions and recognisable repertoire over raw volume.

1. **OpenScore, including Orchestra now.** CC0 editions; structured metadata and source provenance. Orchestra is particularly relevant to this repertoire. Ingest score data separately from SA annotations and remote recordings. [Lieder](https://github.com/OpenScore/Lieder), [quartets](https://github.com/OpenScore/StringQuartets), [orchestra](https://github.com/MarkGotham/Hauptstimme).
2. **Mutopia.** Editable LilyPond and per-piece licences, with derivative MIDI/PDF already available. Select PD/CC0/BY items; escalate SA/OAL according to local policy. [Source tree](https://github.com/MutopiaProject/MutopiaProject).
3. **Open Goldberg / OpenWTC.** Strong score–studio-recording joins for a Bach shelf. Preserve CC0 evidence and locate allowed editable-score delivery rather than accessing MuseScore.com. [Goldberg](https://opengoldbergvariations.org/), [OpenWTC](https://commons.wikimedia.org/wiki/Category:Open_Well-Tempered_Clavier).
4. **PDMX, filtered.** Best expansion corpus after curation: conflict-free, valid assets, identified PD/CC0 underlying repertoire/edition, then quality and instrumentation. Retain dataset-level credit. [Pinned v9](https://zenodo.org/records/15571083).
5. **Verified federal band recordings.** Good recording partner for matching scores; preserve per-file source and territorial caveats, and separately check composition/arrangement. [Marine Band collection](https://commons.wikimedia.org/wiki/Category:Audio_files_of_music_by_the_United_States_Marine_Band).
6. **Musopen's explicitly released recording sets.** The two cited Archive items really show PDM 1.0 and CC0 respectively; those are uploader/source declarations to preserve, not inferred from the composition. [PDM collection](https://archive.org/details/MusopenCollectionAsFlac), [CC0 Kickstarter collection](https://archive.org/details/MusopenKickstarterRecordingsLossless).
7. **OpenGameArt author-published MIDI/audio packs.** Useful modern/game shelf; retain the specific author's licence and credits, not the site's name as a blanket licence. [Confirmed CC0 example](https://opengameart.org/content/original-midi-album).
8. **music21 corpus, individually verified; IMSLP for discovery.** Retain the report's file-by-file advice. KernScores remains a candidate, but this check could not fetch its host successfully, so it is not newly confirmed. [music21](https://github.com/cuthbertLab/music21), [IMSLP API](https://imslp.org/wiki/IMSLP:API).
9. **Incompetech CC BY recordings; permissive FMA tracks.** Useful audio shelves with attribution; inspect extended Incompetech score packs before claiming a complete score/audio join. FMA must be filtered by exact track licence. [Incompetech agent documentation](https://incompetech.com/agent-section/), [FMA dataset](https://github.com/mdeff/fma).

**Keynata is a confirmed CC0-declared generated-content source and the closest structural precedent**, but place potential imports on a separate audition/provenance track: this library's quality bar calls for recognisable pieces, and its metadata screening is not independent rights verification. MusicNet is worth mining for candidate joins, not indiscriminately importing. ASAP/MAESTRO/MSMD remain excluded for NC licensing. Pixabay is excluded from redistributable inventory.

## MCP versus JSON API: agree with the architecture, modify its rationale

Keep **static JSON first, optional thin MCP later**. The existing catalogue/per-item JSON and CLI already implement the useful core. A live search API is justified by scale or server-side work, not by the label “agent-facing.” Keynata and Incompetech validate static delivery; Epidemic validates catalogue MCP delivery. Calling Incompetech the “only” working agent pattern is unnecessary.

MCP should reuse the same records and licence checks. `licence_check` must take the intended asset/use: an existing recording, score redistribution, or a new score render can have different outcomes. Return exact licence URLs, credit, source evidence and caveats; do not collapse everything to a single “safe” boolean. Rendering also requires a permitted soundfont. Treat rendering as optional local computation, while search/get work with a remote catalogue. No second catalogue database is needed.
